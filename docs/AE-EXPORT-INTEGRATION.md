# Подключённый экспорт After Effects

Исходники: `../game-assets/export/`. PNG и JSON в этой папке сохранены без изменений.
Полный предоставленный каталог — `archer.json`: несмотря на имя, он описывает
лучника, пушку, замок, рыцаря и турель. `animations.json` содержит только первые
три объекта. В импортированной версии `shoot` и `attack` обозначают одну атаку.

## Что работает

- Замок и передняя стена ворот `castle-gate-cover`: все 120 кадров при 30 fps,
  зациклено. Передний слой повторяет текущий кадр фасада, поэтому обе части
  синхронны при смене кадров, паузе и переходе к началу цикла.
  Новый фон подключён в меню и бою.
- Рыцарь: walk 0–15, attack 16–36. Лучник: idle 0–2, attack 0–19.
- Пушка: reveal 0–19, attack 20–39. Турель: reveal 0–29, attack 32–61.
- Reveal запускается один раз при установке оружия. После атаки оружие и
  персонажи возвращаются к idle. Враги используют прежнюю графику.
- Солдат начинает движение внутри ворот, под передней стеной; после выхода
  переходит на передний слой поля. Парапет скрывает основания оружия и ноги лучника.
- Стрела и круглое ядро вылетают на настраиваемом кадре атаки. Стрела вращается
  по касательной траектории. Один выстрел пушки показывает одно ядро и попадания
  по всем целям, определённым симуляцией.
- У турели нет отдельной пули: вспышка уже есть в её attack. Попадание показывает
  эффект, короткое белое мигание врага и число урона. Попадания в одну цель
  за 300 мс объединяются в одно число. HP берётся из существующей симуляции.
- Урон и награды определяет симуляция; полёт снаряда — визуальное подтверждение,
  которое не пересчитывает урон повторно.

## Слои и координаты

`src/castle/siegeArtConfig.json` содержит точки крепления в пикселях исходного
холста 512×256 и глубины. Все четыре слоя замка используют общие origin,
позицию, масштаб, поворот и прозрачность; ручные смещения между PNG не нужны.

| Объект | Глубина |
|---|---:|
| castle-gate, задник проёма | 20 |
| castle, анимированный фасад | 22 |
| солдат в воротах | 23 |
| castle-gate-cover, передняя стена ворот | 24 |
| лучники, турель и пушка | 26 |
| castle-cover, передние парапеты | 30 |
| солдаты на поле | 42 |

Точки gate/archer/turret/mortar находятся в `castle.mounts`. Точки muzzle в
`attacks` заданы относительно опорной точки спрайта персонажа/оружия в пикселях
его кадра. `releaseFrame` — абсолютный индекс кадра исходного спрайтлиста.
Текущие точки выбраны по предоставленному рисунку; их можно уточнить в JSON.

## Замена стрел и ядер

В `siegeArtConfig.json → projectiles` есть отдельные варианты `arrow`,
`fireArrow`, `cannonball`. Меняются размер, цвет, длительность полёта,
высота дуги и поправка направления картинки. Изначально стрела использует
имеющуюся текстуру `cardboard-arrow`, а ядро рисуется кругом с бликом.

Для собственной PNG положи её, например, в `public/assets/projectiles/` и
укажи `file: "/assets/projectiles/cannonball.png"`. Она загрузится автоматически.
Для уже загруженного атласа можно указать его `texture` и существующую
анимацию в `animation`; в этом случае `file` оставь `null`.
Картинка стрелы по умолчанию направлена влево (`angleOffset: 180`); для
картинки, направленной вправо, используй `0`. После изменения JSON пересобери
production; dev-сервер применит изменения при перезагрузке.

## Выявленные особенности исходников

- У `cannon.png` размер 1920×3072: 5×8 ячеек 384×384, всего 40 кадров.
  Заявленный в JSON idle 39–58 выходит за пределы изображения. По уточнению
  автора неподвижный кадр 39 выбран намеренно: ожидание пушки должно быть
  стоп-кадром. Подъём и другие движения в idle не нужны.
- `turret.reveal` был зациклен; подключён как одноразовое появление.
- В исходниках нет отдельных hurt/dead у новых защитников. Для этих событий
  сохраняется кадр того же персонажа, а смерть оформляется исчезновением.
- У knight отдельный idle не предоставлен: используется неподвижный кадр ходьбы.

## Повторный импорт

Из каталога проекта:

```powershell
python scripts/import-ae-export.py
```

Нужен Python с Pillow. Скрипт читает исходники, проверяет диапазоны и создаёт
`public/assets/ae-export/` и `src/castle/exportedArt.json`. Длинные PNG замка
(7680 px) и турели (6144 px) разбиты на multi-atlas страницы не больше 2048 px.
Каждый кадр сохраняет исходное разрешение и прозрачность. Между кадрами есть
защитные отступы, а runtime WebP сохраняются без потерь. Не редактируй
сгенерированные атласы вручную: изменения потеряются при повторном импорте.

Исходный JSON описывает кадры и анимации; `siegeArtConfig.json` отдельно
описывает игровое расположение, слои и снаряды.
`castle-gate-cover.png` импортируется как спрайтлист с настройками `castle`
автоматически; отдельная запись в исходном JSON для него не требуется.
